## 5. 第二步：把数值矩阵渲染成图像

Stage 1返回21×21、0/1、只读numpy矩阵；渲染层为它增加白边并显示，保持编码主体及历史轨迹不变。

| 接口 | 作用 |
|---|---|
| `RenderOptions` | 约束至少4模块quiet zone和正整数模块像素 |
| `render_qr(matrix)` | 创建独立正方形Figure，默认V1图像为290×290像素 |
| `draw_matrix(axes, matrix)` | 在调用方已有Axes中重绘，供GUI复用画布 |

[渲染器](../qr_app/presentation/renderer.py)固定0白1黑、最近邻、等比例，不显示坐标轴。输入矩阵在校验通过后才绘制；非法输入不会先清除旧Axes。渲染器不负责生成二维码、打开窗口或自动保存文件。

**290×290是独立`render_qr()`的默认尺寸。正式GUI导出使用当前Figure大小，文件外形可能为矩形，但二维码模块保持正方形并保留白边。** 这一区别已在Information中说明。

## 6. 第三步：实现PNG保存与文件保护

文件：[保存说明](png_export.md)、[image_export.py](../qr_app/presentation/image_export.py)、[png_dialog.py](../qr_app/presentation/png_dialog.py)。

保存顺序为：用户点击Save PNG → 选择路径 → 必要时确认覆盖 → 完整编码到目标目录的临时文件 → 发布文件 → 返回真实`SavedArtifact`。

- 父目录必须存在，目标使用`.png`扩展名；没有扩展名时由对话框补齐。
- 已有文件默认不覆盖，用户确认后才替换；拒绝或取消均保留当前二维码。
- 编码或正常文件替换失败不会先截断已有目标文件，错误反馈与生成状态分开。
- 保存导出现有Figure，不重新请求服务、不替换当前Qt画布。

自动化对话框测试使用预设响应，覆盖确认、取消和失败。已有Windows消息框交互记录，但尚缺正式原生文件选择器的完整人工验收记录。

## 7. 第四步：连接正式生成页面与状态

文件：[main_gui.py](../main_gui.py)、[gui.py](../qr_app/presentation/gui.py)、[main_window.py](../qr_app/presentation/main_window.py)、[generation_panel.py](../qr_app/presentation/generation_panel.py)。

实际数据流如下：

```text
文本草稿
  → 点击Generate，固定本次提交文本
  → QRRequest(source=GUI)
  → QRService.generate_qr(request)
  → QRResult：结果、矩阵、错误/警告、请求ID、实际参数、真实步骤
  → draw_matrix() + Qt画布显示
  → 用户显式Save PNG，导出现有图像
```

GUI沿用基础限制：单一Byte段、严格ISO-8859-1、最多17字节、V1/L/Mask0。输入原文不trim或截断；GUI段落换行按LF提交，自动视觉折行不新增换行字节。

| 用户操作或结果 | 实际状态与保护 |
|---|---|
| 启动、输入、清空草稿 | 不自动生成；实时提示字节数或不支持字符 |
| 点击Generate | 建立新请求ID，提交一次，锁定相关控件 |
| 成功 | 展示图像及对应提交文本、实际参数和已完成步骤数 |
| 修改已有成功结果的草稿 | 标记Not updated，禁用保存；改回匹配的成功提交文本可恢复保存 |
| 新生成失败 | 清除旧二维码，保留输入，禁用保存，展示本次错误和真实部分步骤 |
| 生成成功但显示失败 | 保留生成成功事实，提示图像不可用并禁用保存 |
| 保存取消或失败 | 当前有效二维码仍保留，可以重试 |
| 切到Information再返回 | 不生成、不丢草稿、不改变请求与结果对应关系 |

不支持字符失败有0个完成步骤；超容量失败保留已完成的字符转换1步。GUI显示这些真实结果，不自行补造算法过程。

## 8. 第五步：实现Information与安全说明

[Information实现](../qr_app/presentation/information.py)包含六节：快速开始、信息表示、输入规则与容量、数据完整性与错误、隐私安全、保存与扫码。左侧导航、Input rules入口和F1均可进入，支持分节跳转和返回。

核心说明覆盖“文本→字节→位流→纠错→矩阵→图像”，并解释19个数据码字、7个ECC、21×21主体与quiet zone。换行`41 0A 42`和空格`41 20 42`分别举例，帮助用户理解输入不同会生成不同内容。

安全内容明确QR不是加密，RS不负责认证；应用本地处理，不自动打开或验证URL；用户需防范钓鱼并保护导出的二维码。默认没有自动使用历史，Clear input仅清草稿，不会删除已保存PNG。

说明页只读，阻断外部网址、文件及嵌入资源加载；用户文本按普通文字显示，不插入帮助HTML。8项专项测试验证这些边界与切页状态。
