## 2. 基本信息与考查目标（第1—2页）

- 课程：Programming in Python，课程代码 **CS2PP**。
- 作业：**Python Application Group Project — QR Application – CLI, GUI, and Extensions**。
- 类型：小组作业，含个人评分部分；占课程总成绩 **60%**。
- 人数：理想为5人，允许部分小组4人；本组按4人规划。成员应来自同一实验课组。
- 预计工作量：每人约24小时。
- 不适用Self-Certification Extension。
- 主要考查：Python算法与应用；命令式、函数式、面向对象三种范式；第三方库整合；清晰、高效、规范的代码。
- 从用户文本**自行实现QR编码过程**，通过CLI与GUI/网站生成、显示并保存可扫描二维码；每人再做一项不同扩展。

## 5. Stage1：基础QR数据生成（第3—4页）

| 需求ID | 硬性要求 |
|---|---|
| B01 | 从命令行动态接受用户输入文本，例如短URL或消息 |
| B02 | 按QR标准Byte Mode默认字符集转换为位流；第13页对照工具提示ISO-8859-1 |
| B03 | 使用reedsolo生成Level L的Reed–Solomon数据纠错码字 |
| B04 | 组织正确二维矩阵，0白1黑；必须使用numpy |
| B05 | 正确处理功能图案、分隔区、时序、dark module、终止和填充、格式信息；按实际版本处理对齐图案 |
| B06 | 格式信息由纠错等级和掩码模式生成；其纠错位自行实现，不是由reedsolo替代全部工作 |
| B07 | 基础使用Version1与Mask0，数值数组可以输出到屏幕 |
| B08 | 演示指定的五个字符串，各有带注释的编码过程文件 |
| B09 | 若处理失败，仍报告失败前完成的步骤，不能只输出一条笼统报错 |
| B10 | 此阶段完成并文档化后再进入下一阶段 |

指定输入必须原样使用，不增加首尾空白：

| 序号 | 文本 | 文件名示例 |
|---|---|---|
| 1 | `known` | `demo_1.txt` |
| 2 | `We've succeeded!` | `demo_2.txt` |
| 3 | `~¡256_-_aA&ñ` | `demo_3.txt` |
| 4 | `From α to ɷ...` | `demo_4.txt` |
| 5 | `Sugarplum_Fairy_Nightmare` | `demo_5.txt` |

日志展示内容可包括：模式、长度、位串、码字、网格、掩码前后状态、掩码图案等；关键是清楚证明过程与正确性。五份文件不意味着五个输入都必须成功。按默认字符集和V1/L容量，第4项涉及不支持字符，第5项涉及超出基础容量的错误边界，应正确解释并保留轨迹。

评分表举例V1/L为21×21矩阵、19数据码字+7ECC码字。V1本身无对齐图案，V2才需要按其规范加入；不要为了机械照抄“alignment”在V1错误添加图案。

## 7. Stage3：个人扩展（第4—5页）

每人从六项中**唯一选择一项，组内不重复**。主要由本人在个人分支、独立模块内开发，最终合入main。四人组按每人一项完成四项，不要求六项全做。

| 编号 | 可选方向 | 任务内容 | 本组建议归属 |
|---|---|---|---|
| E01 | 版本与纠错等级 | V1/V2、L/M/Q/H；默认自动确定能容纳数据的最低纠错等级；用户可选版本/等级；容量、警告与特征日志 | A |
| E02 | 完整掩码 | 全部8掩码、全部4类惩罚评分；默认最优、可手选；记录并向用户展示模式与评分 | B |
| E03 | 分步教学可视化 | 对用户输入，以带注释的逐步画面解释QR构建变化；理想情况下可手动控制步骤和保存某步图像 | C |
| E04 | 无障碍外观定制 | 颜色/形状/边框/大小/滤镜/logo等选择；维持可扫描；考虑色觉、视力、亮度、旧设备；预设说明与风险警告 | 不选 |
| E05 | 使用日志与分析 | pandas和外部文件记录每次请求；时间、唯一ID、文本、版本、ECC、掩码、用户选项、是否成功；展示简单累计分析图 | D |
| E06 | 图像反向解码，挑战项 | 从规范QR图像检测模块、提取位、解码文本；可假设标准视角黑白方块及本组支持的规格 | 不选 |

本组分配是建议，不是教师指定。E01中自动版本/等级的顺序需要明确，不应将原文“最低等级”静默改成“最高等级”。

共同的开发要求：

- 每人必须创建有清楚作者标识的Python模块，至少一个函数或类被主项目导入使用。
- 修改本人模块以外的代码要明确标注作者，并与他人沟通依赖与冲突。
- 配置GitLab CI，含linting和至少3个非平凡单元测试；个人评分表也要求三项有意义的测试及解释。本组据此按**每人至少3个**规划，而不是4人共3个。
- 个人文档链接测试，提供流水线所有任务成功的证据。
- 个人文档展示扩展完整功能；最终应用展示所有已选扩展一起运行。

## 15. AI使用边界（第12页）

AI类别是“May be used to support work”，允许用于初步理解、解释概念、总结材料、头脑风暴、探索陌生主题和规划结构。

本规划及本摘要属于前期理解/结构规划参考，不应原样作为评分成果。团队自行实现、撰写并在README如实说明辅助工具使用。材料截图中的一般提醒不能替代第12页更具体的限制。
