## 2. 什么属于公共接口

不仅是函数名，还包括：参数类型/顺序/单位、返回字段、错误形式、数组方向、是否改动输入、是否写文件、资源释放责任、事件是否产生新请求，以及CSV字段含义。

例如将 `matrix` 改成 `qr_matrix`、将容量从bytes改成bits、将None改成0、将一次调用改为自动记两条日志，即使函数名没有变化，也会影响公共契约。

本项目只用进程内Python调用，不为了协作增加HTTP API、远程服务或复杂插件框架。

## 4. 唯一生成入口与装配

### 4.1 选择实例服务，避免隐藏全局配置

冻结为 `qr_app.service.QRService.generate_qr(request: QRRequest) -> QRResult`。前文的 `generate_qr(request)` 指这个绑定方法的调用形态，不再另外维护一套模块级生成流程。

启动端构造服务，GUIController和CLI接收同一形态的生成方法；测试可以注入同签名的假服务来统计调用或制造故障。不需要依赖注入框架。

| 装配入口 | 约定 |
|---|---|
| `QRService(*, version_selector=None, mask_selector=None, usage_logger=None)` | 可选依赖在CLI/GUI启动时传入；构造本身不生成QR、不写日志 |
| `service.generate_qr(request)` | 一个接受的请求执行一次，返回生成结果和独立日志状态 |
| `service.capabilities` | 只读能力集合，由真实装配推导，如version_ecc/mask_selection/usage_logging；不能假装未实现的能力可用 |

baseline始终使用共享V1/L/Mask0实现，不依赖个人扩展先存在。extended的版本/ECC选择需要已接入的version_selector；mask_selector尚未接入时只允许显式Mask0，Auto或1..7返回FEATURE_UNAVAILABLE。界面按实际能力开放控件。

usage_logger未接入时日志状态是not_enabled；最终日志扩展完成后，CLI/GUI均装配它，并记录baseline/extended的成功及失败请求。不能只在GUI接日志，漏掉CLI。

### 4.2 业务失败与调用错误分开

- 对结构有效、可识别的QRRequest，参数非法、空输入、不支持字符、超限等返回失败QRResult，保留ID和真实步骤，并按09尝试记录。
- 非QRRequest对象、错误字段类型、无效ID或缺失有效时间等属于调用契约错误，抛出 `QRContractError`，code为INVALID_REQUEST；入口边界安全呈现并诊断，不把任意对象强制转为用户原文。
- 核心内部的可预期业务异常由服务统一转成QRResult。非预期 `Exception` 在服务边界转换为INTERNAL_GENERATION_ERROR并留必要诊断，不吞掉退出/中断信号。
- 日志、图像保存和分析读取的错误各有独立状态/异常，不覆盖生成错误或把成功QR改成失败。

## 5. 公共对象字段冻结

类型注释中 `T或None` 表示允许缺失；tuple/只读Mapping表示调用方不应修改。实际可以用dataclass/Enum实现，但不因为使用frozen dataclass就假定嵌套字典、numpy数组自动不可变。

### 5.1 QRRequest：用户要求什么

| 字段 | 内存类型 | 约束 |
|---|---|---|
| `request_id` | str | 合法UUID字符串，一次提交建立一次 |
| `timestamp` | 带时区datetime | 在接受提交时建立；CSV序列化成ISO 8601；拒绝无时区时间 |
| `text` | str | 原始输入，不trim、不截断 |
| `source` | cli/gui枚举 | 入口给定 |
| `mode` | baseline/extended枚举 | 按08解释 |
| `version` | int或auto枚举 | 仅1、2或auto；拒绝bool冒充整数 |
| `ecc_level` | L/M/Q/H或auto枚举 | 请求值，不当成实际值 |
| `mask_id` | int或auto枚举 | 0..7或auto；0有效 |
| `capture_steps` | bool | 是否保留轨迹；五份基础演示必须True |
| `options` | 只读Mapping | 当前额外键白名单为空，默认为空；以后新增需在契约登记，未知键为INVALID_OPTION |

mode/版本/ECC/mask/capture_steps已是明确字段，不重复从options读取另一套互相冲突的值。不在options中塞任意路径、控件、账户或服务对象。界面草稿复制成请求后，编辑草稿不能改变该请求。

### 5.2 EncodingPlan：实际要怎样编码

| 字段 | 类型/单位 | 不变量 |
|---|---|---|
| `version` / `ecc_level` | 实际整数/等级 | 不允许auto |
| `matrix_size` | int，模块数 | 17 + 4×version，不含quiet zone |
| `capacity_bytes` | int，bytes | 与08的单一Byte段容量一致 |
| `data_codewords` | int，码字数 | 此字段是数量，不是内容 |
| `ecc_codewords_per_block` | int，码字数/块 | 按规格表，不把总ECC数当单块数 |
| `block_groups` | tuple[BlockGroup] | 每项含block_count和data_codewords_per_block，顺序稳定 |
| `total_codewords` | int，码字数 | 数据总数 + 每块ECC数×块数 |
| `remainder_bits` | int，bits | 按对应版本规范 |
| `character_count_bits` | int，bits | V1/V2 Byte模式为8 |

`sum(group.block_count × group.data_codewords_per_block)` 等于data_codewords；资源表抄录错误不能靠放宽校验通过。失败前没有可用plan时留None，不将超限的手选组合假装成已通过计划。

### 5.3 位流、码字和矩阵

| 对象 | 冻结字段/类型 | 单位和方向 |
|---|---|---|
| `EncodedData` | `byte_length: int`、`data_codewords: bytes` | 编码后实际原文长度；填充后数据码字内容 |
| `FinalCodewords` | `interleaved_codewords: bytes`、`bitstream: tuple[int,...]` | 前者是数据/ECC交织后码字；后者含版本余数位 |
| `MatrixLayout` | `modules`、`reserved_mask`、`version` | 未掩码布局；保留区与主体同形 |
| `PenaltyBreakdown` | `n1/n2/n3/n4/total: int` | 非负整数；total等于四项和 |
| `MaskSelection` | `mask_id`、`final_matrix`、`penalty_scores` | 最终实际掩码，完整矩阵，按0..7索引的评分映射 |

对外矩阵为 `numpy.ndarray`，主体dtype为uint8且仅0/1，保留区dtype为bool。索引统一 `[row, col]`，左上角为(0,0)，行向下、列向右；0白1黑。主体不含quiet zone，内部临时占位值不能泄漏给掩码、渲染和结果。

位流是整数0/1的有序tuple，码字是bytes；不把 `"0101"` 字符串或整数256混入。`len(bitstream) = 8 × len(interleaved_codewords) + plan.remainder_bits`，数据码字数和总码字数分别与plan吻合。

扩展模式手动掩码也返回八个候选评分；baseline的penalty_scores为空映射，不能伪造八个0分。掩码操作跳过所有reserved模块；随后专门写格式信息可以改变格式预留区，测试时不要把“格式写入”误判为掩码翻转。

### 5.4 TraceStep与TraceCollector

| 接口/字段 | 约定 |
|---|---|
| `TraceStep` | step_id、title、explanation、payload_type、payload |
| `payload_type` | text/bits/codewords/matrix/scores |
| `step_id` | 同一结果内唯一、顺序由步骤tuple决定；候选专有步骤带mask编号 |
| `TraceCollector(enabled: bool)` | 服务每次请求新建，位于拟建 `qr_app/tracing.py`；不跨请求共享 |
| `record(step_id, title, explanation, payload_type, payload)` | 立即复制需要保留的字典/数组；数组快照设只读；不写文件 |
| `steps() -> tuple[TraceStep,...]` | 返回已完成的真实步骤；enabled=False时为空tuple |

各计算函数通过可选的关键字参数trace接收同一个收集器。函数中途失败，之前record的步骤仍由服务持有，避免只能在函数成功返回后才拿到全部轨迹。每个步骤只由一个阶段登记，服务不再合并同一步骤的另一份副本。

复制与只读约定防止意外修改，不宣称是对恶意代码的安全隔离。失败时可以没有矩阵，但必须保留已经完成且capture_steps允许保留的步骤；关闭轨迹时仍返回明确错误，不伪造步骤供界面显示。

### 5.5 QRResult：发生了什么

| 字段 | 类型 | 约束 |
|---|---|---|
| `request_id` | str | 与接受的请求一致 |
| `generation_success` | bool | 只描述QR生成，不描述日志/保存 |
| `byte_length` | int或None | 严格编码成功后才有完整字节数 |
| `plan` | EncodingPlan或None | 已解析计划；允许后续阶段失败时保留 |
| `matrix` | ndarray或None | 仅成功时有最终只读矩阵 |
| `mask_id` | int或None | 真正选定/应用时填写，0有效 |
| `penalty_scores` | 只读Mapping | 无评分时为空，不能用0冒充未知 |
| `trace_steps` | tuple[TraceStep,...] | 本请求真实步骤，独立快照 |
| `warnings` | tuple[str,...] | 可展示提示；程序不通过匹配提示文字决定业务分支 |
| `error_code` / `error_message` | str或None | 成功均为None；失败有明确生成错误 |
| `error_details` | 只读Mapping | 安全结构化信息，如byte_length/capacity_bytes/字符索引；不含堆栈/凭据 |
| `logging_status` | LogStatus | 返回给调用方前已确定日志处理结果 |
| `selection_policy_version` | str | 当前input_rules_v1，真实反映选择规则 |

成功时plan/matrix/mask均完整，error_code和error_message为空；失败时matrix为空。服务不把请求的auto写进实际参数。warnings和日志状态可以在生成成功时同时存在。

## 6. 计算函数接口

以下是规划签名，关键字trace默认None；表内函数不直接读GUI或写使用CSV。

| 模块/接口 | 输入→输出 | 关键约束 |
|---|---|---|
| `byte_encoder.encode_text(text: str) -> bytes` | 原文→严格ISO-8859-1字节 | 字符不支持报业务错误；空输入应用规则由服务先检查 |
| `version_policy.select_plan(byte_length, version, ecc_level, mode) -> EncodingPlan` | 长度+请求值→实际计划 | 按08顺序；不可用组合报业务错误；baseline用共享固定计划路径 |
| `byte_encoder.encode_data(data_bytes: bytes, plan, *, trace=None) -> EncodedData` | 已编码字节→模式/长度/数据/填充后的数据码字 | **统一接收bytes，不同时支持text和bytes两种隐含语义** |
| `error_correction.build_final_codewords(data_codewords: bytes, plan, *, trace=None) -> FinalCodewords` | 数据码字→RS/交织码字及含余数位的bitstream | V2多块按规范处理，输入bytes不被修改 |
| `matrix_builder.build_matrix(bitstream, plan, *, trace=None) -> MatrixLayout` | 最终位流→未掩码布局 | 跳过保留区，位流长度匹配 |
| `format_info.build_format_bits(ecc_level, mask_id) -> tuple[int,...]` | 实际ECC/mask→15个最终格式位 | 自行处理格式纠错与规定异或；不是数据RS码字 |
| `fixed_mask.apply_fixed_mask_zero(layout, plan, *, trace=None) -> MaskSelection` | 布局→Mask0及格式信息完整结果 | baseline独立可用；不修改传入布局 |
| `mask_selector.select_mask(layout, plan, mask_id, *, trace=None) -> MaskSelection` | 布局→八候选评分和最终选择 | 每候选写相应格式后评分，不改原布局 |

`version_selector`装配的是上表select_plan形态的函数，`mask_selector`装配的是select_mask形态的函数。辅助函数可以在模块内自定名称，但不能私下改变上表跨模块调用。

本版解决旧架构中的歧义：先encode_text得到字节数再选plan，之后encode_data只接收该bytes，不在两个阶段分别用不同字符集重新解释输入。轨迹由同一个TraceCollector保存。

## 7. 步骤、渲染、保存和分析接口

### 7.1 StepVisualizer

| 接口 | 行为 |
|---|---|
| `StepVisualizer(trace_steps)` | 取得本次只读轨迹，不编码、不写文件 |
| `step_count` / `current_index` | 步骤数；空序列时current_index为None |
| `current_step() -> TraceStep或None` | 空序列返回None |
| `next()` / `previous()` | 返回移动后的步骤；边界停留原位置，空序列返回None |
| `set_index(index)` | 合法索引切换；越界抛IndexError，属于调用错误，不是生成失败 |

Qt页面根据step_count和索引启用按钮；导出获取当前步骤的真实载荷，调用统一renderer/保存器，不在步骤对象里藏另一套编码算法。

### 7.2 renderer和资源所有权

| 接口 | 行为和资源责任 |
|---|---|
| `render_qr(matrix, render_options) -> Figure` | 构造新Figure并绘图，不隐式保存、不创建Qt应用 |
| `draw_matrix(axes, matrix, render_options) -> None` | 在调用方Axes绘图，显式增加显示quiet zone；不修改原主体矩阵 |
| `save_figure(figure, target_path: Path, *, overwrite=False) -> SavedArtifact` | 仅写明确目标；PNG首版；已有文件未允许覆盖则报保存错误 |
| `SavedArtifact` | 至少实际path和media_type；返回成功意味着文件已写完，不能填预期路径冒充完成 |

render_options建议采用明确结构：quiet_zone_modules（默认4，不能小于4）、module_pixels（正整数）。首版保持黑白、最近邻、正方形比例；窗口布局和文本标签不塞进它。屏幕DPI/实际显示仍需人工扫码验收。

**谁创建或持有Figure，谁负责其生命周期；save_figure不自动关闭调用方传入的Figure。** GUI画布保存后仍需显示，不能因保存把它关闭。CLI创建的临时图由CLI在收尾时释放；Qt页面负责画布替换/关闭时的释放。这个约定取代旧说明中“保存函数负责关闭所有图像”的含混表述。

取消QFileDialog在GUI处理，不调用save_figure。保存异常 `ArtifactSaveError` 含安全code/message，由展示层呈现，不改变QRResult或追加生成日志。

### 7.3 UsageLogger与统计

| 接口/对象 | 冻结语义 |
|---|---|
| `UsageLogger(path: Path)` | 路径由启动配置给定，不取自用户原文；构造不清空已有文件 |
| `append_attempt(request, result) -> LogStatus` | 显式持久化；同ID同内容防重，同ID不同内容失败，不静默覆盖 |
| `LogStatus` | state、error_code、message；公开state为not_enabled/written/already_recorded/failed |
| `summarise(filters: UsageFilter) -> UsageSummary` | 读取已记录、有效并去重的数据；不追加生成记录 |
| `UsageFilter` | start_inclusive/end_exclusive（可空、带时区datetime）、status（all/success/failure）、display_timezone |
| `UsageSummary` | total_requests、success_count、failure_count、success_rate、ecc_counts、time_buckets，以及实际重复/排除说明 |

success_rate为0—1比值，零记录为None而不是伪造0%成功；GUI转百分数并显示分母。ecc_counts保留UNRESOLVED或明确范围，time_buckets按展示时区稳定排序。日期界面将结束日转换成下一日零点的排他边界，避免漏掉当天晚间请求。

CSV序列化以09为准：请求timestamp转ISO字符串；options连同mode/capture_steps等明确选择组成允许字段的user_options JSON；请求值与实际值分列。原文NA/NULL/00123和空白保留。分析读文件/格式错误用 `UsageReadError` 返回到展示边界，不伪造“暂无记录”。

服务先构造生成结果，再调用append_attempt，最后将返回的LogStatus放入最终QRResult。logger不递归调用服务，也不为“记录日志状态”再写第二条请求。构建中尚未尝试写日志的临时状态不作为“已记录”返回给UI。

## 8. 错误形式与副作用清单

业务错误建议由 `QRGenerationError(code, message, details)` 在核心抛出，服务捕获后统一转换；08定义的INVALID_OPTION、EMPTY_INPUT、UNSUPPORTED_CHARACTER、CAPACITY_EXCEEDED等名称保持一致。

| 边界 | 允许的副作用 | 失败如何传递 |
|---|---|---|
| encode/select/build/mask | 仅可选内存trace记录；不修改输入 | 业务异常→服务转QRResult |
| generate_qr | 内存编排，装配后一次使用日志写入 | 有效请求返回QRResult；调用契约错误抛QRContractError |
| record/steps | 在本请求收集器保存独立快照 | 内部错误诊断，不伪造步骤 |
| append_attempt | 指定本地CSV写入 | LogStatus.failed；不覆盖生成错误 |
| summarise | 指定CSV读取与聚合 | UsageReadError；无文件的正常空历史与损坏区分 |
| render/draw | 新图或调用方Axes更新 | 展示层安全反馈，QR生成结果保持 |
| save_figure | 指定PNG写入 | ArtifactSaveError；不新增生成请求 |
| Qt控件事件 | 草稿、页面状态、显式调用 | 由busy/finally收尾，防重复信号与重入 |

细节错误、路径、堆栈、用户原文不随意塞进可公开的message。真正需要原文的使用日志按09保护；证据采用非敏感输入。

## 9. 文件责任和“修改权限”

这里分三层：团队约定负责人与评审；GitHub仓库/分支的实际权限；本机文件系统权限。指定文件负责人不会自动禁止其他协作者编辑，也不会自动设置GitHub或Windows权限。

### 9.1 所有成员都可提出修改，责任角色负责协调

下列均为待认领角色，不是新的人事分配。

| 路径/类别 | 协调角色 | 重点评审方 |
|---|---|---|
| models/errors/tracing | 公共契约协调 | 服务及受影响的核心/展示/日志使用者 |
| service.py | 集成协调 | 本次接入模块和展示调用方 |
| core/byte_encoder、error_correction | 编码功能 | 矩阵使用方；核对独立规范/码字 |
| core/matrix_builder、format_info、fixed_mask | 矩阵功能 | 编码和掩码使用方 |
| qr_capacity_v1_v2.json | 规格资源协调 | 编码、矩阵功能共同复核 |
| extensions/version_policy、mask_selector | 相应功能 | 服务调用方和相邻算法功能 |
| extensions/step_visualizer | 步骤功能 | Qt步骤页/导出使用方 |
| extensions/usage_logger | 日志功能 | 服务和分析页使用方 |
| presentation/ | 展示/导出功能 | 相应服务、步骤/统计提供方 |
| tests/ | 对应功能，公共集成为集成协调 | 至少一位非作者复核预期依据 |
| 依赖、CI、Git忽略/仓库规则 | 环境与集成协调 | 所有受影响环境/调用方 |
| 规划、README、证据索引 | 文档/证据协调 | 提供真实功能事实的成员 |

负责人不享有跳过评审的特权。其他成员在自己的分支可以修改公共文件，但应在PR说明接口影响并请相关方复核。跨模块改动在代码中记录作者/原因，并保留真实提交历史。

### 9.2 修改等级

| 等级 | 例子 | 处理 |
|---|---|---|
| 内部修改 | 局部变量、函数内部优化，不改变输出/异常/副作用 | 常规PR；跑对应功能测试，至少一位非作者评审 |
| 兼容扩展 | 新增有默认值的可选参数、明确可忽略的可选字段 | 更新本文和调用例，确认消费者真能忽略；跑相关契约/集成测试 |
| 破坏性/行为变更 | 改名/删字段、改单位/dtype/空值/错误、自动顺序、所有权或记录次数 | 先说明迁移与影响，经使用方确认；提供同PR原子更新或临时兼容适配；更新版本并复验 |
| 环境/安全边界 | 新依赖、Qt绑定、日志路径/隐私、CI门槛、main保护 | 单独清楚说明理由、课程依据与复现；复核受影响环境和证据 |

不能把放宽测试、吞异常、忽略失败任务当成“兼容修复”。更换生成字段和只改一处按钮代码一样需要消费者检查。

## 10. GitHub操作建议与平台实施边界

当前建议规则：个人功能分支开发 → PR → 受影响测试 → 非作者评审 → 合并main；禁止强推/重写共享main历史，避免最后一天才首次集成。普通开发者使用足够的写入权限，仓库设置由待指定管理员协调，不预先授予所有人管理员权限。

| 建议的平台设置 | 用途/限制 |
|---|---|
| main要求PR | 把公共改动集中到可审查入口 |
| 至少1个非作者批准 | 小组规模4人，避免自己批准自己；多项消费者确认可由兼任角色覆盖 |
| 已实际存在的lint/test检查通过 | 状态检查名称须与真实CI一致；CI未建前不宣称已强制绿灯 |
| 限制force push/删除main | 保护共享历史 |
| CODEOWNERS（以后可选） | 指定评审请求对象；本身不禁止修改文件，需要结合保护设置才可能强制owner评审 |

这些目前仅为建议，**本轮没有查询、创建或修改GitHub角色、ruleset、branch protection、CODEOWNERS或CI**。可用功能受仓库类型/可见性/账户方案影响，未核验前不承诺可强制某项；平台不能自动强制时，仍执行团队PR和证据约定。

没有真实GitHub用户名和已认领角色前，不生成虚假的CODEOWNERS，也不把A/B/C/D写成账户。正式学校GitLab/CI对接仍按09处理，不把GitHub权限名和GitLab Maintainer混为一谈。

## 11. 一次公共修改的完整流程

1. 在issue/PR描述当前接口、问题和受影响调用者；只改内部逻辑时注明公共行为不变。
2. 破坏性变更先登记新旧字段/行为、迁移方式与测试；真实负责人未分配时由团队共同确认，不冒充已批准。
3. 从当前main同步到自己的功能分支，避免私自覆盖他人的开发文件。
4. 修改提供方、所有必要调用方、测试和文档；用兼容层分阶段迁移时说明何时移除，不能留下永久双重标准。
5. 跑对应单元/契约/集成检查，列出已运行和未运行项；有CI时附真实链接。
6. 请求至少一位非作者评审，收集受影响功能方确认；解决评论后再合并。
7. 合并后核对main和证据版本，若公共行为变更，重新运行受影响演示场景，不复用失效旧截图。

冲突处理要逐段理解双方意图，不一键“保留我的”或删掉测试来通过。紧急修复仍保留短说明、检查和非作者复核；回退公共修改优先新增反向提交保留历史，再恢复受影响调用方，不能通过重写main掩盖变更。

## 13. 编码前冻结与后续契约验收

### 冻结清单

- [ ] 确认实例服务入口及三项可选装配方式；baseline可独立运行。
- [ ] 确认QRRequest/QRResult/Plan字段、datetime与CSV序列化边界。
- [ ] encode_data统一传bytes，bitstream/码字/矩阵单位与方向明确。
- [ ] 确认TraceCollector共享到每个阶段，失败前已record步骤不会丢失。
- [ ] 确认矩阵/字典不被调用者意外修改，历史快照独立。
- [ ] 确认生成错误、日志状态、保存/分析异常分开。
- [ ] 确认save_figure不关闭GUI画布，资源由创建/持有方释放。
- [ ] 确认文件协调角色待认领、至少一位非作者评审、平台设置仍待实施。

### 有意义的契约验收场景

| 场景 | 核查 |
|---|---|
| 同一请求由CLI/GUI提交 | 业务结果和错误一致，展示差异不改变字节与参数 |
| 不支持字符/容量失败 | ID保留、matrix为空、实际值按进度可空，已完成轨迹可展示 |
| 阶段中途失败 | 已记录步骤仍在，未完成步骤不出现 |
| 掩码和步骤操作 | 原布局/早期快照不被后续修改，格式写入与掩码操作分清 |
| 单次生成/保存/翻页 | 服务/日志调用次数符合08/09，不重复产生请求 |
| 日志不可写 | QR生成状态保持，LogStatus.failed真实可见 |
| GUI保存成功 | 图像仍可显示和继续交互，文件与选定结果一致 |
| 空历史/损坏历史 | 空数据为零记录和None成功率；损坏明确报错，不假装空历史 |
| 修改公共字段 | 提供方、消费者和证据一起迁移，不能只测字段“存在” |

测试采用独立预期、规范参考、不变量和真实故障；不只镜像实现。具体算法测试仍遵循每人至少3个非平凡测试及已有验收清单，本文件不把新增表格项目冒充作业额外硬性测试数。
